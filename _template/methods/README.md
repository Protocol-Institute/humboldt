# Methods Inventory

This directory contains documented research techniques — named, repeatable procedures that the researcher applies to generate or test candidates.

## Why a methods inventory?

Human researchers develop characteristic analytical moves — things they do habitually when stuck, when they need to generate new ideas, or when they need to test an existing claim. Making these explicit serves two purposes:

1. **Consistency:** the researcher applies them systematically rather than ad hoc
2. **Evolution:** techniques can be refined, retired, or extended based on what works

## Technique types

| Type | Purpose | Triggers |
|------|---------|---------|
| **Generative** | Produce new candidate laws or hypotheses | When stuck; when starting a new investigation; scheduled rotations |
| **Analytical** | Test, refine, or scope existing candidates | After a candidate law is drafted; when confidence is unclear |
| **Dual-use** | Both | — |

## Required vs. optional techniques

**Required (every researcher should have these):**
- At least one generative technique for finding new candidates
- At least one analytical technique for testing candidates

**Recommended:**
- M-001 (Random Links) — universally applicable generative technique

**Optional (useful for some research programs):**
- M-002 (Canonical Domains) — valuable for researchers who work across multiple domains
- M-003 (Deep Read) — valuable when there are foundational texts worth internalizing at depth

## Naming convention

Techniques are numbered M-NNN and named descriptively. The number is permanent; the name may evolve as the technique is refined.

## Application history

Each technique file contains an application history table — when the technique was used and what it produced. This enables meta-research: which techniques are most productive, which are underused, which should be retired.
