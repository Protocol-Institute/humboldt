retrieval. Reads only matter for the *optional* evidence-refresh pass in Phase B.

## 5. Build

### 5.1 Artifacts

```
talks/2026-09-23-new-nature/
  brief.md          operator-set: title, audience, duration, framing constraints
  slides.yaml       slide structure — id, title, law_id, bullets, beat, word budget
  track.md          THE talk track: per-slide narration. Generated, then edited.
  audio/slide-NN.mp3
  timing.json       measured per-slide durations (ffprobe) + running total
```

Two consumers read this same source data, not one:

- **The live deck** (§5.4) — the operator's Zoom screen-share instrument. Ephemeral,
  interactive, one big autoplaying audio file per slide.
- **The persistent page** (§5.5, new scope 2026-09-01) — the public, permanent record at
  `humboldt.protocol-institute.org/talks/…`. A normal scrollable article: every slide's
  bullets and full narration text, in order, each with its own audio play button. This is
  what Humboldt's talk *is*, after the room empties — and per risk 7, it's also the
  natural Q&A-ingest source.

`track.md` is the source of truth for narration; `slides.yaml` for what is projected.
Keeping them separate is deliberate — the slide should not be the script. Bullets are
anchors for the room; the narration is the argument.

### 5.2 Code

| Component | Role |
|---|---|
| `prompts/talk.md` | Fable-tier prompt. Inputs: `brief.md`, `slides.yaml`, the 7 law records. Output: per-slide narration under a hard word budget. |
| `agent/talk.py` | `draft` (generate track) · `voice` (render audio) · `time` (measure) · `check` (budget/lint). Uses `synthesizer.synthesize_full()` like the other engines. |
| `humboldt-site/build.py` | New `_build_talk_page()`, matching the existing `_build_*` pattern (`_page()` wrapper, same nav/fonts/palette as `/reading/`, `/laws/`) → `dist/talks/2026-09-23-new-nature/index.html`. Copies `audio/*.mp3` alongside it. Wired into `build()` and, once a second talk ever exists, a small `/talks/` index page. |

### 5.3 CLI

```bash
python3 -m agent.humboldt talk draft            # laws + brief → track.md (Opus; --dry-run supported)
python3 -m agent.humboldt talk voice            # track.md → audio/*.mp3 (say → ffmpeg)
python3 -m agent.humboldt talk voice --voice X  # audition a different say voice
python3 -m agent.humboldt talk time             # per-slide + total runtime vs the 15:00 target / 20:00 cap
python3 -m agent.humboldt talk check            # word budgets, TTS hazards, unvoiced slides
```

`talk check` is the guardrail that makes a machine-voiced talk survivable. It flags what
`say` reads badly and a human reader would silently repair: bare law ids (`L-004` → "law
four"), arXiv ids, URLs, parentheticals over ~12 words, em-dash chains, and any slide over
its word budget. Run before every `voice`.

### 5.4 Deck

Self-contained HTML + CSS, no external libraries — same constraints the site already
works under. Keyboard nav (←/→/space), one `<audio>` per slide, and a presenter readout
showing measured slide duration and elapsed total.

**Autoplay:** browsers block audio until a user gesture. Arrow-key advance *is* a gesture,
so slides 2–12 play on advance; slide 01 needs an explicit start button. This is the kind
of thing that is discovered in the room if it is not built for deliberately.

### 5.5 Persistent page (new scope, 2026-09-01)

**URL:** `humboldt.protocol-institute.org/talks/2026-09-23-new-nature/` — date-prefixed
slug, matching the source directory and the existing `talks/` naming convention (not a
title-slug like `/talks/some-candidate-laws-of-new-nature/`; consistent, collision-proof
if a second talk is ever added, and machine-derivable from the folder name with no
separate naming step).

**Shape:** a single scrollable page, not a slideshow. For each of the 15 slides, in
order: the slide title, its bullets (rendered as the room would have seen them, small
and quiet — they're anchors, not the content), the full narration paragraph from
`track.md` as the actual body copy, and a `<audio controls>` element per slide sourced
from `audio/slide-NN.mp3`. Same page style as `/reading/` and `/laws/` — DM Sans body,
Cormorant Garamond headings, the site's existing teal accent (`#2A6B6B`) — reusing
`_page()` so it inherits nav, footer, and fonts for free rather than inventing a second
visual language for one page.

Law slides carry their stage/confidence badge (heavy-lift/supported, valley/provisional,
etc.) the same way `/laws/` already does — this page is a *presentation* of records that
live at `/laws/`, so cross-link each law slide's heading to its `/laws/L-NNN` entry
rather than duplicating the full record.

**Build dependency chain** (nothing here is buildable until the step above it exists):
corpus reads back (done, this session) → Phase B evidence refresh, if it changes any
quoted example → `talk draft` regenerated if laws/slides changed → `talk check` clean →
voice audition + `talk voice` → `talk time` → **then** `_build_talk_page()` can run,
since it needs both final `track.md` text and rendered `audio/*.mp3` to exist. Building
the page is therefore the last step of Phase C, not a parallel one.

**Not built yet:** no `_build_talk()`/`_build_talk_page()` in `build.py`, no `audio/`
directory, no `timing.json` — Phase C hasn't started. This section plans it; it doesn't
implement it.

## 6. Risks

1. **Seven laws leaves no per-law counterexample beat.** Partially superseded: L-001 and
   L-002 now carry live counterevidence in their own case-study slides (§3); slide 13
   ("Held to account") still carries the shared beat for the other five. Watch for the
   talk reading as a list rather than an argument; if it does at rehearsal, the fix is to
   drop L-006 (weakest, §6.2) rather than to speed up.
2. **L-006's four examples are all software** (APIs, identity, naming, network stack). Its
   cross-domain generality is asserted, not shown — and cross-domain evidence is the entire
   basis on which this talk claims these are *laws*. Either present it as explicitly
   software-scoped, or use the Phase B pass to find a non-software example. Do not let it
   go on stage implying breadth it does not have.
3. **The deliverable is "a URL" and this branch has never deployed to production.** Every
   `redesign-2026-08` deploy has been a Preview (`project_site_deploy_preview_trap`).
   **Elevated 2026-09-01: no longer deferrable.** The persistent page (§5.5) was scoped
   specifically to live at `humboldt.protocol-institute.org/talks/…` — the real production
   domain, named explicitly, not "a URL" in the abstract. A Preview URL does not satisfy
   this deliverable; it isn't the site's real address and Preview URLs are not guaranteed
   stable. Decide by **2026-09-16** (unchanged deadline, now hard): merge `redesign-2026-08`
   to `main`, or another path that actually lands content on the production domain. This
   still fails silently — `publish-site` reports success on a Preview deploy too — so
   confirm with `agent.publish_site.is_production_deploy()` after whichever fix lands, not
   just a green CLI exit.
   **2026-09-01: resolved by scheduling, not a separate decision.** The operator set
   `plans/redesign-2026-08.md` Phase 5 (server cutover) to complete by 2026-09-16 — the
   same date this risk already needed. `redesign-2026-08` only merges to `main` after
   Phase 5, and that merge *is* the production deploy this risk is waiting on. So "decide
   by 09-16" is now "Phase 5 lands by 09-16," one milestone, not two. Watch
   `plans/redesign-2026-08.md` §13 for slip; if Phase 5 runs long, this risk slips with it.
4. **Runtime drift** — the standard failure of an operator-advanced deck. Neutralized:
   durations are measured by `ffprobe`, never estimated, and the deck displays elapsed vs
   budget live.
5. **Voice quality is a real audience-experience risk.** `say` is free and honest but
   unmistakably synthetic. Audition 3–4 voices (Daniel en_GB was the probe) on the *actual*
   slide-01 text, not a sample sentence, before committing.
6. **Laws may move before 09-23.** An `induct` sweep or an `assess` promotion can change a
   stage or statement mid-project. `talk draft` is regenerable, so re-run it after any law
   change and re-check timing — do not hand-patch `track.md` and let it drift from records.
7. **Live Q&A needs the talk content in Humboldt's retrievable context, and this is not
   yet designed** (added to scope 2026-08-18 — brief.md). The operator intends to run the
   10-minute Q&A slot through the public site chat rather than answering personally. If
   the deck/track aren't ingested before 09-23, Humboldt will field questions about a talk
   it has no retrievable memory of just having given. Needs: what gets ingested (track.md?
   a synthesized summary?), which namespace, and — critically — *timing*: too early and an
   audience member could ask about it before the talk exists publicly; too late and it
   misses the session. Design during Phase C/D once track.md is final.
   **2026-09-01: the persistent page (§5.5) is the natural ingest source** — it's already
   the full track text, already chunked slide-by-slide, and already getting a `bib-NNNN`
   entry is a one-line addition to the existing `humboldt ingest` path rather than a new
   mechanism. Timing still needs a decision: ingest right after the page publishes (page
   goes live pre-talk for the persistent-URL requirement in §5.5, which reopens the
   too-early risk this item already named) or hold the page itself back until the talk
   slot starts. Resolve alongside risk 3's deploy timing, not separately.

## 8. What this is not

Not a rendered video (decision §1). Not a c3po-style corpus demo — the talk is about
Humboldt's own findings, and the corpus appears only as evidence provenance. Not a
comprehensive inventory tour: nine `exploration` laws are deliberately excluded, and the
talk should say so rather than imply the seven are all there is.
